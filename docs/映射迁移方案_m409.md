## 一、先把关键事实摆平：改名的活，两条路一样多

Yarn 与 Mojmap **不是两套 API，是同一份 Minecraft 的两套名字**。

```
Yarn  ： net.minecraft.item.ItemStack        player.getStackInHand(hand)
Mojmap： net.minecraft.world.item.ItemStack  player.getItemInHand(hand)
```

所以无论走哪条路，**那 15 215 行 xplat 业务代码的名字都得改一遍**，工作量完全一样。
区别只在**改完之后你手里有几份代码**：

| | 单独建文件夹移植 | 全仓转 Mojmap |
|---|---|---|
| 改名工作量 | 一样 | 一样 |
| 改完之后 | **两份**业务代码（Yarn 一份、Mojmap 一份） | **一份** |
| 以后加一台机器 | **写两遍**，还得防止两边漂移 | 写一遍 |
| 以后修一个 bug | **修两遍**，漏一边就是"这个版本有那个版本没有" | 修一遍 |
| 现在能玩的 Fabric 格 | **零风险**（一个字不动） | 迁移期会动，需分批+CI 兜 |
| 将来 26.x 那格 | 还要**再抄第三份** | 直接共用 |

**单独建文件夹唯一的真优势是"风险隔离"**——你现在能玩的那份完全不受影响。
这个优势是真的，但它可以用「开分支 + 分批 + 每批全绿才推」买到，不必用"永久双份维护"去换。

## 二、决定性的一条：26.x 那格已经在写 Mojang 名了

`versions/26.2/`（m370 立的新世代 bootstrap）**代码本来就是 Mojang 官方名**——
上游 Yarn/Intermediary 对新世代已停更，那格没有别的选择。

于是账变成这样：

- **不转**：1.21.1 业务（Yarn）↔ NeoForge（Mojmap）↔ 26.x（Mojmap）三者互不通用 → 最终**三份**业务代码。
- **转**：1.21.1 / NeoForge / 26.x 全是 Mojmap → **一份** xplat 供全矩阵共用，
  各加载器只写薄薄的适配层（m405 判定的"结构性接口"那一小撮）。

**这条把方向基本定死了**：转 Mojmap 不只是为了 NeoForge，更是为了 26.x——
而 26.x 是作者点名要支持的四锚点之一。

集中度高是好消息：**改名收益前几十个类型就吃掉大半**，剩下的长尾靠编译器逐个报出来。
方法名（`getStackInHand`→`getItemInHand` 这类）没法只数类型，得靠工具与编译器。

## 四、工具链（不靠手改，也不靠猜）

1. **首选：Loom 自带的 `migrateMappings` 任务**——它就是干这个的（在作者机器上跑，maven 可达）。
   先在分支上对**一个小包**试跑，看产出质量再决定要不要全量。
2. **兜底：自建对照表**。两段桥都在 GitHub 上拿得到（沙箱已实测可下载）：
   - `FabricMC/intermediary` → `mappings/1.21.1.tiny`：obf ↔ intermediary ✔
   - `FabricMC/yarn` @1.21.1 → 逐类 `.mapping`：intermediary ↔ yarn ✔
   缺的是 obf ↔ Mojmap 那半段（Mojang 官方 proguard 文件，沙箱域名不可达，作者本地/Loom 能取）。
   两段拼起来就是 **yarn ↔ mojmap 的机器对照表**，脚本批量替换 + 编译器兜底。
3. **判官照旧**：CI 五 job（含 Gradle 真编译、GameTest 用例集）+ 十三道离线闸。

## 五、节奏（风险摊平，主分支随时可玩）

1. 开 `mojmap` 分支，主分支照常可玩、可出包。
2. Fabric 根构建换映射：`mappings loom.officialMojangMappings()`；**mixin 六枚的靶点名同步改**。
3. 分批改名，**每批 CI 全绿才推**，顺序=从薄到厚：
   `net/`(24 个 payload) → `item/`+`node/` → `registry/`+`screen/` → `client/` → 压轴两大件
   （`StructureCoreBlockEntity` 4 186 行 / `StructureCoreScreen` 3 074 行）。
4. 全绿后合并回主分支，然后 NeoForge 那格把 `xplat/` 挂上去——**那一刻第二个加载器才算真的活了**。
5. 26.2 那格顺带白捡：xplat 从此对它也可编（还要过 26.x 自己的 API 差异，另算）。

## 六、明确不做

- **不建第二份业务副本**（m408 已否决，本稿第一节把账算细了）。
- **不靠第三方桥**（Sinytra Connector 之类）：不可控、随上游死活。
- **不夹带**：迁移期间不塞新玩法/新机器，避免"改名炸了还是新功能炸了"分不清。
