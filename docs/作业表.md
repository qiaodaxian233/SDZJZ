## 三、下一刀

**A4：连线归并徽章 m193**（A5 三片已收官，依赖解除）。主线 `StructureCoreScreen` renderBg 里 `seBundles`（组↔存储
归并线，原 626~688）与 `mmBundles`（组↔机器归并线，原 690~760）两段 + `// ===== m193 连线归并 =====` 助手区（原 1736~，
归并锚点算式=组框缘中点/卡缘）。**先逐句对**：归并的输入是 m507 主线已装配的分组共享表（gm/gRect/nGid）与两代同名的
`WireRenderer`，输出是 `drawWire` 调用 + `×N` 徽章——预计世代差为零，可下沉成 `GroupFrameRenderer` 或独立 `WireBundler`
共用件；但 m505 普查稿记着**这两段夹在存储线/机器线的正常绘制循环里**（归并与非归并线同一循环分流），切段前先看区间
（m487 血案），别把普通连线绘制切走。配置 `canvasGroupBundleWires` 两代共用（common）。1.20.1 侧对应的是
`renderBg` 里 m458 存储边循环与 connections 循环——要在那两个循环里加同样的分流。

**贯穿 B 线的结论（五次逐句对反复验证，A5a 是第六次——服务端六方法归一后 diff=0）**：「两代行为有差异」几乎
从不意味着「代码没法共用」——差异通常只住在很少的几行里，收进世代口（带默认值的钩子/
Impl 接口），剩下的就能整段共用。B3/B4/B5 全部照此办理，B5 还多验证了一条边界：
**世代口必须是"零加载器符号"的**——业务逻辑和它依赖的具体接口类型要分开看，后者若是
FTA/加载器类型，哪怕两代代码逐行相同也不能塞进 xplat，这层"薄壳"必须留在各自源集
（m503→m504 那次返工的教训，`layer_gate` 硬闸看着）。
**开工纪律（m495 教训）**：先把两代对应段**逐句对一遍**再决定能不能共用——
不要从"行为描述不同"推"代码没法共用"，m473/m475 那句「不是照抄能解决的」就是这么推错的
（真去对，二十行相同、三行不同）。**引用 m4xx 排刀稿结论前先问「它预设的路线还在吗」（m502 规矩）。**
**闸的自证纪律（m506 教训）**：新立/改闸时，自证要用它声称能防的那次血案**重放**，不是随手捏一个错——
第 19 闸被 m504 的语句级裸调用形状考了一次才发现从来抓不到那一类。
