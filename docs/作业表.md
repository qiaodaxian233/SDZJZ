## 一、取活规则（我自己按这个排，不用问）

按序号从上往下取第一个**不阻塞**的：

1. **修构建失败 / 回归** —— 作者贴来的编译错、实机故障。**随时插队，最高优先**。
2. **作者当轮点名的事** —— 优先于本表任何既定项。
3. **当前分片的收尾项** —— 已开的分片先做完再开新的（避免半成品堆积）。
4. **无阻塞的主线活** —— 按本表「待办」区顺序。
5. **需要拍板的** —— 移到「阻塞区」，**不猜、不擅自选**，在汇报时提一句即可。

## 二、每刀标准流程（照做，别靠记忆）

**搬代码时**（m483~m492 全部教训固化）：
- [ ] 1. **先查 `docs/世代API对照表.md`** —— 要搬的原文里有没有 1.21 专属 API？有就查现成世代口。
- [ ] 2. **整段搬，不重写** —— 原文粘过来，只改真正编译不过的地方。判据：改完 `diff` 得跟原文逐句对得上。
- [ ] 3. **连调用点一起搬** —— 函数体只是一半，**调用点的参数怎么算往往才是那些刀号真正住的地方**（m492 血案）。
- [ ] 4. **切段别按行号盲切** —— 先看区间里有没有夹着别的成员（m487 把构造器一起删了）。
- [ ] 5. 注释里的刀号、血案记录、"看起来像 bug 其实不是"的说明 —— **一起搬，不许精简**。

**验证时**（每刀必跑）：
- [ ] 6. 两代 javac 冒烟 → **`python3 docs/tools_smoke_filter.py <日志>`**（不要手写 grep，m491 血案）
- [ ] 7. **20 道闸全绿**（一条命令跑完，见下）
- [ ] 8. 版本号 = DEVLOG 最新刀号；DEVLOG + HANDOVER + **本表**同刀更新
- [ ] 9. commit（中文一行带刀号）+ push
- [ ] 10. 汇报时说清**实机预期**（作者据此验），并说明**这刀改没改存档/运行时路径**
