## 一、取活规则（我自己按这个排，不用问）

按序号从上往下取第一个**不阻塞**的：

1. **修构建失败 / 回归** —— 作者贴来的编译错、实机故障。**随时插队，最高优先**。
2. **作者当轮点名的事** —— 优先于本表任何既定项。
3. **当前分片的收尾项** —— 已开的分片先做完再开新的（避免半成品堆积）。
4. **无阻塞的主线活** —— 按本表「待办」区顺序。
5. **需要拍板的** —— 移到「阻塞区」，**不猜、不擅自选**，在汇报时提一句即可。

**并行纪律（m509 撞出来的）**：作者可能同时开着多个会话取活，本表「下一刀」不是锁。**开工前 fetch 一次、push 前再 fetch 一次**对表 HEAD；
若同项已被别的会话推上去，先读对方 DEVLOG 条目，再决定是补刀（做对方没做的那半、退役重复件）还是换项——不重做、不覆盖。

**主线画布改动波及检查（m523 评审②，A12 收官前有效）**：凡一刀碰了主线 `StructureCoreScreen`，收尾必问「改的段在 1.20.1 `CanvasScreen120` 有没有搬入副本」——锚点 `grep -n 'm164b\|m519\|m193\|m184\|m352' versions/1.20.1/.../CanvasScreen120.java`（悬停聚焦块 / 拖线三段 / 归并分流 / 选缘与柱心）；有副本=同刀同步或在 D 线登记欠账一行，**不许静默漂**。A12 下沉完这条自动作废。

**普查稿防过期（m523 评审④）**：`docs/主线对比1201_全量缺口与超大工作台普查_m521.md` 是快照——**S 线每收官一刀、或两代缺口表有变化（新上挂/新退回/新方块屏），同刀在该稿末尾「状态更新」段追加一行**（刀号+改了哪格），别让它三个月后变第二张没人敢信的长文档。
