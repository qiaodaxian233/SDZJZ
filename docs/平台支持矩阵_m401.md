## 一、作者定的目标

- **版本四锚点**：`1.20.1` / `1.21.1` / `26.1` / `26.2`——**小版本不做**（1.21.5、26.1.2 这种不单独出包）。
- **加载器**：Fabric（现状）+ **NeoForge** + **Forge**。
- **联动**：**JEI** + **机械动力（Create）**。

## 四、真正的拦路虎：1.20.1 不只是"换加载器"

1.21.1 → 1.20.1 是**物品数据模型代际差**：1.20.5 才有 DataComponent，1.20.1 只有旧 `ItemStack.getNbt()`。
本仓**全部节点状态**（z 族/b 族键、过滤名单、账本、组件保真红线）都建立在
`DataComponentTypes.CUSTOM_DATA` 上，`NodeTags` 是唯一读写口——好消息是**只有一个口**，
坏消息是 1.20.1 那格要多一层 `ItemDataAccess` SPI（组件版/NBT 版两实现），
且"精确存储/组件物品不混堆不变裸"的红线要在旧模型上重证一遍。
**这格的成本≈其余三格之和**，是最该单独拍板要不要做的一格。

## 六、分阶段路线（每格一笔 mNNN，做一步推一步）

1. **P1 SPI 补齐**（不动行为、Fabric 单实现先行，CI 全绿即算过）：
   `NetworkPlatform`（payload 注册/收发口，124 用点收成 1 个口）→ `StoragePlatform`（transfer 69 用点）→
   `EventPlatform`/`RenderPlatform`/`KeyPlatform`/`RegistryPlatform`。每抽一族一笔，`tools_loader_scan`
   数字掉多少就是进度条。
2. **P2 三源集骨架**：`common/`（已有）+ `fabric/` + `neoforge/`，构建方案二选一（**待拍板**，见下）。
3. **P3 NeoForge 1.21.1 首格落地**：注册/网络/能力/屏三件套接上，出第一个 Neo jar。
4. **P4 26.1/26.2**：Fabric 侧接现有 bootstrap，Neo 侧复用 P3 实现。
5. **P5 Forge 三格**（若拍板要）：Neo 与 Forge 在 1.20.1 几乎同源，1.21.1+ 需各写一份注册/事件。
6. **P6 1.20.1 回迁**：`ItemDataAccess` 组件↔NBT 双实现 + 红线重证。
7. **P7 联动**：JEI 插件分加载器；Create 联动（限 1.20.1/1.21.1）。

## 七、需要作者拍板的四条（缺省=按推荐）

1. **Forge 那三格要不要**？1.21.1 起社区主力是 NeoForge，Forge 是纯额外维护成本（每笔改动 ×3 加载器）。
   **推荐**：先只做 Fabric+NeoForge 四代八格，Forge 等有人真的提需求再说；1.20.1 那格如果做，
   Forge 优先级反而最高（Create 生态主场）。
2. **构建方案**：**MultiLoader-Template 手写**（无第三方运行时依赖，构建脚本自己维护）
   vs **Architectury**（省事，但吃它的 API 和版本节奏）。**推荐前者**——本仓 `common/`+`platform/`
   已经是手写多源集的形状，引 Architectury 等于把已建的地基推平重来。
3. **1.20.1 那格做不做**？成本≈其余三格之和（组件↔NBT 代际差）。**推荐**：排最后，
   等 Fabric/Neo 新世代全绿后再评估。
4. **机械动力具体要联动什么**？现在只有"适配 Create"四个字，可选面有：
   ①**物流对接**（Create 的传送带/漏斗与本模组存储网络互通）②**JEI 分类共存**（已有 JEI 插件即可）
   ③**动力/应力**（本模组是免费型无能量系统，接应力=改经济模型，事大）。**推荐 ①**，②白捡，③另行拍板。

## 八、不变的红线（移植期间一条都不许破）

- `common/` 硬闸：零 MC/Fabric/Mojang 依赖、Object 不存字段、Platform 字段硬顶。
- 服务端权威：所有 C2S 先验资格/材料（换加载器时网络层最容易一起把校验搬丢）。
- 有界解码（m291）、写包预算（m269）、精确存储组件保真——每格移植后各跑一遍既有 GameTest 与十二把离线尺。
