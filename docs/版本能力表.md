# 版本能力表（m533 首版，每刀同步；最近更新 m534）

> 回答一个问题：**某项功能在某个版本格做到了哪一步**。口径来自评估报告 §八（m533 入账），七态分列，
> 不再把「可注册 / 配方可解析 / 可运行 / 可存档」混成一个「✅」。
>
> **七态**：**定**=定义存在（Machines/常量/协议）· **注**=注册成功（游戏里能拿到）· **配**=配方可解析
> （**只检查**结果件与材料 id 在该版本注册表里能解析——判官②口径，不证明生存链）· **得**=生存可取得
> （材料链在该版本原版里存在且能造出）· **运**=行为可运行（tick/交互真跑，有判官或实机）· **存**=保存/恢复
> 正确（退出再进/重启后原样，有判官或实机）· **客**=客户端验收完成（作者实机清单过）。
>
> **记号**：✅ 有证据（判官/CI/记档刀号）· ◐ 部分（备注说明）· ✗ 无 · **？未验**（没有证据就写未验，不猜）·
> — 不适用。证据优先级：CI 判官 > 作者实机记档 > 代码存在。
>
> **维护规矩**：动了任何一格就同刀改这张表（与 DEVLOG/HANDOVER/作业表同刀）；不确定就写「？」再在备注说清缺哪种证据。
