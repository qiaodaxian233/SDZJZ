# 主线(1.21.1) ↔ 1.20.1 全量缺口普查 + 超大工作台移植分片（m521，零代码笔）

> 作者点名两句：「我说的是超大工作台」「你能不能根据 1.21.1 的东西去对比」。前几十刀我一直是按作业表一件件搬，
> 没有一张**以主线为基准的整体缺口表**，于是作者看到的"没做"我账上也没登记（超大工作台就是：作业表四条线里根本没有它）。
> 本稿用 `git ls-files` 与资源目录**机械对比**，不靠记忆；此后每次作者问"X 没做吗"先查这张表。

## 一、对比方法

- 类：`src`+`xplat`（主线源集）vs `versions/1.20.1` 全部 `.java`；xplat 里已挂 1.20.1 白名单的算两代共用。
- 资源：`assets/sdzjz/models/{item,block}` 两目录逐名比。
- 网络包：主线 `net/*Payload` 24 个 vs 1.20.1 `*Payloads120` 内 record。
- 功能：以主线 HANDOVER「四屏」「机器系统」为纲，逐项标 ✅（两代同源）/ ◑（部分）/ ✗（本世代无）。

**一个新世代口（SB2 开工第一件）**：`ResourceLocation.parse(id)` 的现成口是 `SciSkin.Gfx.id`（m484），但它在 **client** 包——`SuperBenchScreenHandler`

`ItemData.Impl`（两代各一句：`ResourceLocation.parse` / `new ResourceLocation`），顺带把 `remove(DataComponents.CUSTOM_NAME)`（1.20.1=`resetHoverName()`）也收进去。
**不要**为省事把 `SciSkin.Gfx` 从 client 挪出来。
